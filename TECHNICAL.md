# Устройство PrivetAntigravity

Код написан на Go, без встроенного браузера. Windows использует Win32 и службу LocalSystem, Linux — терминальное меню и пользовательскую службу systemd. Для запуска достаточно готового файла.

## Файлы клиента

Поиск ограничен папками установки, каталогами CLI и расширений. Символические ссылки при обходе не раскрываются. Можно явно указать дополнительную папку.

Для `agy` и Language Server проверяется формат PE или ELF и архитектура x64/ARM64. Меняются строки одинаковой длины: `ineligible` → `inexigible`, `https_proxy` → `PA_LS_PROXY`. Это клиентский патч, доступ на стороне сервера он не подтверждает. Для `main.js` и `extension.js` меняется только распознанная проверка после `resetIsTierGCPTos()`: выражение `this.<свойство>.isGoogleInternal` заменяется на `true` с пробелами до исходной длины. Несколько совпадений считаются неоднозначностью, файл пропускается.

Архивы ASAR и неизвестные проверки не изменяются. Релизные пакеты самого патчера выпускаются для x86_64; обработчик файлов также распознаёт ARM64-бинарники внутри установки.

## Сохранение и восстановление

До записи создаются копия по SHA-256 и запись в `backups/records.json`. Для каждого поколения сохраняются исходный хеш, хеш патча и путь. Запись выполняется через временный файл в той же папке; файл сбрасывается на диск и переименовывается. Перед записью повторно проверяется исходный хеш, после — результат.

Откат использует последнее поколение для каждого пути. Он проверяет целевой файл и содержимое копии. Обновлённые или посторонне изменённые файлы не заменяются. Применение нескольких файлов идёт последовательно; при ошибках журнал показывает частичный результат. Общей транзакции на все компоненты нет.

## Соединения

HTTP CONNECT-прокси слушает только `127.0.0.1:53147` и принимает соединения на порт 443. Адреса частной сети и локальной машины отбрасываются. Одновременно обслуживается до 64 туннелей.

Для `cloudcode-pa.googleapis.com`, `daily-cloudcode-pa.googleapis.com`, `aicode.googleapis.com` используются резолверы из `config.json`. По умолчанию это `https://dns.dns-ai.ru/dns-query` и `tls://dns.dns-ai.ru`. Эталонные адреса запрашиваются через `https://dns.google/dns-query`. Предпочтение получают отличающиеся адреса; перед использованием проверяется TLS-сертификат на исходное имя Google. Затем клиент сам устанавливает своё TLS-соединение через туннель. Проверка сертификатов не отключается. При недоступности маршрутов пробуется прямое соединение.

Встроенные внешние серверы общедоступны, не принадлежат приложению и могут изменить условия или прекратить работу. У пользователя есть возможность задать свои адреса. Отличие DNS-адреса и успешный TLS не доказывают, что запрос модели будет принят: в текущем выпуске маршруты не выбираются по результату чата.

В Windows NRPT-правила с меткой `PrivetAntigravity-v1` касаются только трёх точных имён. Локальный DNS на `127.0.0.54:53` возвращает IPv4 loopback и пустой ответ для IPv6. TLS-приёмник на `127.0.0.54:443` читает имя SNI из ClientHello и передаёт исходные зашифрованные байты по выбранному маршруту. Корневой сертификат не создаётся.

Служба и исполняемый файл находятся в `%ProgramData%\PrivetAntigravity`; DACL разрешает изменение администраторам и SYSTEM, остальным — чтение и запуск. Установленные правила удаляются по собственной метке. Общий DNS сетевых адаптеров и системный HTTPS_PROXY не меняются.

В Linux запуск задаёт переменные прокси только процессу Antigravity и его дочерним процессам. Файл службы: `~/.config/systemd/user/privetantigravity.service`. Права root для работающей службы не требуются.

## Проверка и обновления

Диагностика проверяет подключение и сертификат, без входа в аккаунт. Ответ модели пользователь проверяет в Antigravity. Автоматическое обновление самого патчера отсутствует: новый выпуск устанавливается вручную.

Фоновая проверка каждые 30 секунд сравнивает размер и время изменения файлов. Уже обработанный файл пропускается; при новой версии создаётся новая копия. В Linux неудачный доступ к системному файлу записывается в журнал; для повторного патча потребуется открыть меню и подтвердить повышение прав. В Windows службу запускает SYSTEM.
